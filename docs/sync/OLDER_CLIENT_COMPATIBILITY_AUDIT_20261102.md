## Mandatory end-to-end acceptance, not merely unit tests

For each of at least iOS 3.1.8, Android 3.1.8, proposed 3.1.9 iOS, proposed 3.1.9 Android and Portal:
1. **A creates offline** then kills app mid-upload; original IDs and amounts remain after restart; B reads only after exact server acknowledgement.
2. **Parent incomplete:** linked spray/actual must wait or be explicitly held; never create an orphan or present synced.
3. **Same session 2 writers:** later different amounts, mismatched IDs, older clock, newer clock, corrected session. No success on rejected server values; both sides preserved.
4. **New edit during ACK:** save editor B while A's original request is in flight; older result cannot clear the newer intent, across all 8 affected child queue services.
5. **Old client after new client:** preserve new metadata, original recipe, chemical catalogue history, tank actuals, row occurrence coverage and correct write denial/adapter.
6. **Network/permission:** timeout before commit, timeout after commit, 401/403, expired refresh, partial page, zero-row PATCH, RLS-filtered row, account/vineyard switch.
7. **Admin:** hard-stop, soft-delete, archived linked parent, active-device claim; never manufacture journal receipt or discard actuals.
8. **Success:** exact source/build/backend RPC hash and original device receipts for full start, real tank amounts, end, server readback, and other-device convergence.
