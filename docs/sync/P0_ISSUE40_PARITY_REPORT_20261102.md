### Exact local reason remains blocked, not diagnosed as corruption

`LEGACY_ORIGINAL_HELD` is emitted by the per-item index for duplicate Trip/Spray identity, strict decode/validation failure, **or** a valid-but-unverified original (`rpc == null` or verified status not accepted). By itself it cannot distinguish these cases. `LEGACY_EVIDENCE_INSPECTION_HELD` comes from the separate `inspectionAttempts` whole-reader/access catch. That reader does not fail merely because an item is unverified: it decodes all entries, checks duplicates and validates every entry before filtering. A failure could be another entry or store-access problem; the diagnostic does not prove entry 0 is the failing entry.

Strict checks include UUIDs, actor/Trip/input identity, epoch nonnegative, operational planning admission, finite engine hours, Start/acceptance consistency, frozen RPC key and identity allowlists, permitted stage and receipt version/status/identity/hash/time/code. Current-session epoch equality is a separate dispatch/start fence, not the same as the nonnegative validation check. Without original bytes we cannot name a failed key, schema version, operation UUID, actor/epoch or actual attempt stage. Do not trim fields, default missing facts, re-encode or invoke a strict writer to inspect.

No device attached to local ADB. The bounded 100-row runtime-log search found no matching legacy/Trip/Phase5 text; it is not original-handset evidence or exhaustive log history. Next prerequisite is a **protected read-only original-installation export** of `vinetrack_legacy_spray_saves_v1` / `attempts` plus original account/epoch evidence. Hash raw bytes before parsing and inspect each entry separately with the exact installed-schema decoder, capturing allowlisted field/type/reason codes only. Do not paste raw chemicals, requests or credentials into chat. If the signed installation is not exportable, agree a diagnostic-only, non-writing export/inspection route before further changes; no rooting, reinstall or storage clear.
